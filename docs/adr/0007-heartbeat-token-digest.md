# ADR-0007: 心跳令牌摘要与轮换/撤销

- 状态：Accepted
- 日期：2026-10-24

## 背景

心跳上报接口不要求后台任务持有管理员凭证，只凭令牌识别 Monitor。令牌会出现在 URL 路径中，因此数据库泄漏、日志泄漏和令牌轮换都需要明确处理。令牌本身由服务端生成，是高熵随机值，不是用户选择的密码。

## 决策

- 令牌为 32 字节 CSPRNG，base64url 编码（43 字符）。数据库只保存其 SHA-256 十六进制摘要，`token_hash` 全局唯一；比较依赖唯一索引查找，不保存明文或用可逆加密。
- 每个 Monitor 同时最多一个未撤销凭证，由 `(monitor_id) WHERE revoked_at IS NULL` 部分唯一索引保证。凭证记录永久保留用于审计，撤销只写 `revoked_at`。
- 明文令牌只在创建心跳监控项和轮换时返回一次；普通查询、列表和日志都不返回。轮换在同一事务内撤销旧凭证并生成新凭证；撤销是幂等操作。
- 上报接口对无效、已撤销、所属 Monitor 已禁用的令牌统一返回 `404 HEARTBEAT_NOT_FOUND`，不区分原因。成功上报返回 `204`。
- 防护：按令牌每分钟 120 次的进程内限流、1KB 请求体上限、`require-https` 开关（默认关闭，生产环境开启）。每 IP 的粗粒度限流留给部署层（Phase 5 的 Caddy）。

## 备选方案

- bcrypt / Argon2：慢哈希用于低熵密码防暴力破解；这里令牌是 256 位随机值，慢哈希只增加每次上报开销。
- 保存可逆密文：需要密钥管理与轮换，且数据库和密钥同时泄漏时仍可还原，收益低于摘要。
- HMAC-SHA256 + 服务端 pepper：增加一层保护，但引入 pepper 轮换与丢失后全体令牌失效的运维复杂度；当前威胁模型不要求。
- 令牌放在请求头而不是 URL：可以避免代理访问日志泄漏，但与已确定的接口形态和常见心跳 URL 用法不一致；路径方案通过代理日志脱敏处理。
- 按 IP 限流放在应用内：需要额外的状态与清理机制，单实例部署下交给反向代理更简单。

## 后果

- 数据库泄漏不能直接得到可用令牌；但令牌一旦丢失无法找回，只能轮换。
- 令牌出现在 URL 中，Phase 5 必须配置 Caddy 访问日志脱敏或排除 `/api/v1/heartbeats/` 路径；应用自身不记录完整请求 URI。
- SHA-256 的安全性依赖令牌保持 256 位高熵；若将来允许用户自定义低熵令牌，必须重新评估哈希方案。
- 撤销令牌后会按截止时间正常触发超时 Incident；这是"凭证失效"的预期后果，不额外静默关闭 Incident。
