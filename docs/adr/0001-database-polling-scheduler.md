# ADR-0001: 使用数据库轮询调度探测

- 状态：Accepted
- 日期：2026-10-21

## 背景

Phase 1 需要按配置的间隔探测已启用的 Monitor。系统为单实例部署，监控配置与运行状态以 PostgreSQL 为可靠来源，重启后必须继续按配置探测。

## 决策

使用单个 `fixedDelay` tick（默认 1 秒）查询数据库中「已启用且到期」的 Monitor，并提交给有界线程池执行。数据库是调度的唯一事实来源，不在内存中为每个 Monitor 维护独立定时器。

## 备选方案

- 为每个 Monitor 注册内存中的 `ScheduledFuture`：重启后调度状态丢失，CRUD 与调度需要双向同步。
- Quartz：引入额外框架和表结构，超出 MVP 需要。
- 外部调度器：增加部署组件，违背单实例、少依赖原则。

## 后果

- 到期判定最多有一个 tick 间隔的延迟。
- 需要为「已启用 + 到期」查询建立索引。
- 明确假设单实例；未来若支持多实例，必须重新设计调度与互斥。
