# 产品定位：PulseOps

## 愿景
提供一个轻量、可靠、低维护成本的在线监控平台，帮助开发者发现 API 故障、响应超时和后台任务未按时执行等问题。

## 目标用户
### 当前
- 个人开发者。
- 自己维护的网站、HTTP API 和 Spring Boot 服务。
- 使用 Cron、定时任务或脚本执行备份、同步、采集等工作的开发者。

### 未来候选
- 独立开发者和小型团队。
- 需要管理多个项目、历史故障和通知渠道的用户。

## 核心价值
1. 定时检查 HTTP/HTTPS 服务。
2. 通过心跳检查后台任务是否按预期执行。
3. 在故障和恢复时发送通知。
4. 查看历史探测结果、响应时间和故障事件。
5. 使用 Docker Compose 在单台低成本 VPS 上部署。

## 产品差异化假设
- 优先做好定时任务 Heartbeat 监控。
- 对 Java/Spring Boot 开发者友好。
- 部署简单、依赖少、维护成本低。
- 故障状态、告警去重和恢复处理可靠。

这些是待验证假设，不得声称已经形成市场优势。先自用，再邀请少量开发者试用。

## MVP 范围
必须包含：
- HTTP/HTTPS 监控项管理。
- 定时探测、超时和失败分类。
- 探测历史。
- 故障创建、去重和恢复。
- Telegram Bot 通知。
- Heartbeat 监控。
- 基础管理界面。
- 数据保留清理、备份和恢复说明。
- 管理接口认证及基本安全控制。

## 明确非目标
MVP 不实现：
- Kubernetes 或集群级监控。
- 分布式 Agent 网络和多地区探测。
- 完整 APM、分布式追踪和日志平台。
- 多租户商业计费、订阅支付。
- AI 根因分析、RAG 或本地大模型。
- 自动修改或修复被监控的生产系统。
- 任意用户脚本执行。

## 成功定义
- 自己至少有 5 个真实监控目标。
- 故障和恢复场景通过测试。
- 可在低成本 VPS 上稳定运行。
- 备份可以实际恢复。
- 至少邀请 3 位开发者进行真实试用并收集反馈。
- 根据使用证据决定继续、调整定位或暂停，而不是单纯追求功能数量。
