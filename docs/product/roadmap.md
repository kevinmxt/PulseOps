# PulseOps 路线图

## 当前阶段
Phase 1 已完成（验收证据见 `quality/phase1-acceptance.md`）；当前进入 Phase 1.1 — 可靠性修复门槛（源于 2026-10-22 Phase 1 源码审查，见 `reviews/phase1-code-review.md`），完成后进入 Phase 2 — Incident 与通知。

## 阶段顺序

### Phase 0：工程初始化
- [x] 检查现有仓库、开发环境和 Git 状态
- [x] 初始化 Java 21 / Spring Boot / Maven Wrapper
- [x] 配置 PostgreSQL 与 Flyway
- [x] 初始化 Vue 3 + TypeScript + Vite
- [x] 配置本地 Docker Compose
- [x] 建立 README 和基础测试流程

完成条件：新环境按文档可以启动；数据库迁移和基础构建成功；仓库没有真实凭证。

### Phase 1：HTTP 监控核心
- [x] Monitor CRUD
- [x] URL 与配置校验
- [x] 定时探测
- [x] 超时、状态码与错误分类
- [x] CheckResult 持久化
- [x] 基础监控状态查询

完成条件：正常、失败、超时场景可重复测试；禁用监控不再执行；重启后配置仍存在。

### Phase 1.1：可靠性修复门槛（新增）
目标：修复影响结果正确性和公网部署安全边界的问题，不改动产品范围，不做大规模重构。

- [x] 探测配置版本与 in-flight 结果竞态修复
- [ ] 探测语义相关配置变更后立即重探
- [ ] SSRF 特殊用途地址策略明确化并补测试
- [ ] DNS 超时资源边界验证并给出结论
- [ ] 建立 CI（后端 verify、前端 build）并修复 `backend/mvnw` 执行位
- [ ] 更新 Phase 1 验收文档，区分历史测试记录与 CI 证据

完成条件：配置变更竞态测试通过；执行期 SSRF 测试通过；CI 在干净 checkout 中通过。

非目标：认证、Incident、UI、历史数据清理（均属于后续阶段）。

### Phase 2：Incident 与通知
依赖：Phase 1.1 固化的探测结果持久化语义。

- [ ] 连续失败阈值
- [ ] 连续成功恢复阈值
- [ ] Incident 创建、去重和恢复
- [ ] Telegram 通知
- [ ] 通知状态、有限重试和日志

完成条件：不会为同一持续故障重复创建 Incident；通知故障不阻塞探测；恢复事件正确关闭。

### Phase 3：Heartbeat
- [ ] 心跳监控项
- [ ] 高强度随机令牌及安全存储
- [ ] 心跳上报接口
- [ ] 超时扫描
- [ ] 故障与恢复通知

完成条件：有效令牌可上报，无效/撤销令牌被拒绝；超时可触发故障；重复扫描不会创建重复事件。

### Phase 4A：最小可用 UI
- [ ] 监控项列表、创建、编辑、禁用和删除
- [ ] 当前状态、最近检查时间与延迟
- [ ] 历史结果分页、活动 Incident 与通知状态
- [ ] 心跳配置与上报命令展示

非目标：图表大屏、复杂主题、自定义仪表盘。

完成条件：核心功能可仅通过 UI 完成。

### Phase 4B：认证与数据维护（公网前硬门槛）
- [ ] 单用户认证与授权，覆盖所有管理 API
- [ ] 未认证访问返回 401/403 的集成测试
- [ ] 生产 profile 启动检查：公开监听且未启用认证时拒绝启动
- [ ] 历史数据保留策略与分批清理任务
- [ ] 备份与恢复演练

完成条件：未授权访问被拒绝；清理任务遵守保留期限；备份可恢复。

### Phase 5：VPS 部署
前置条件：Phase 4B 已完成；任何管理入口公网可达前认证必须启用。

- [ ] 生产 Compose 配置
- [ ] Caddy / HTTPS
- [ ] 防火墙与 SSH 安全
- [ ] 日志轮转
- [ ] 数据库备份
- [ ] 外部健康检查
- [ ] 升级与回滚文档

完成条件：HTTPS 可访问、数据库不暴露公网、重启可恢复、备份可恢复、连续运行 7 天且无未解决的严重故障。

### Phase 6：试用验证
- [ ] 至少 5 个真实监控目标
- [ ] 邀请 3–5 位开发者试用
- [ ] 收集真实反馈
- [ ] 记录误报、漏报和告警延迟
- [ ] 输出下一阶段决策

## 路线图规则
- 按阶段顺序推进；若要调整顺序，记录原因。
- 未满足验收条件不得标记完成。
- 阶段完成必须附 CI 运行链接（干净 checkout），不能只依据本地测试记录。
- 同一数据库只允许一个启用调度的应用实例；多实例前需完成专门设计与并发测试。
- 不伪造测试、运行或用户反馈证据。
- 当前阶段只实现必要功能，不提前实现未来阶段。
- 每次任务结束后，只更新实际发生变化的状态。
