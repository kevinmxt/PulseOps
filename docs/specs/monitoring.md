# HTTP/HTTPS 监控规范

## 目标
按配置的时间间隔检查目标服务，保存结果并更新监控状态。

## 最小配置
- 名称
- HTTP/HTTPS URL
- HTTP 方法，默认 GET
- 检查间隔
- 连接超时
- 响应超时
- 预期状态码或状态码范围
- 启用状态

所有配置均需服务端校验。

## 执行流程
1. 找出到期且启用的监控项。
2. 提交到有界执行器。
3. 在执行时验证目标 URL 和解析地址。
4. 发起请求并执行超时控制。
5. 分类结果并持久化 CheckResult。
6. 更新连续成功/失败计数及监控状态。
7. 交由 Incident 模块处理状态变化。
8. 交由 Notification 模块处理告警。

## 结果要求
至少记录开始/结束时间、耗时、成功标志、失败类型、HTTP 状态码（适用时）和安全的错误摘要。

失败类型至少包含连接失败、解析器不可用（本地解析并发耗尽）、连接超时、响应超时、非预期状态码和内部探测异常。

## 可靠性
- 单个探测不能无限占用线程。
- 网络请求必须有超时。
- 同一监控项不能因调度重叠而无限并发探测。
- 探测开始时捕获 Monitor 的配置版本和间隔。结果写回仅在配置版本未变化时生效；配置变更期间完成的探测结果直接丢弃，不写入 CheckResult，也不覆盖新配置的状态和 `nextCheckAt`。
- 探测语义配置（`target_url`、`method`、`interval_seconds`、连接/响应超时、期望状态码范围）变化后应立即安排一次探测；`name` 等展示字段变化不触发。Monitor 从禁用变为启用时立即探测。
- 禁用的监控项不得产生新探测；禁用前已开始的探测完成后仍记录结果。
- 单次失败是否触发 Incident 由故障状态机决定，不由探测器直接发送告警。
- 不得因目标异常导致整个应用崩溃。

## 解析器可观测性
DNS 解析通过 `TimeoutHostResolver` 限制同时在途的解析数。许可被长期卡住的解析占满时，新解析会快速失败，并通过以下信号暴露：

| 指标 | 类型 | 含义 |
| --- | --- | --- |
| `resolver.permits.available` | gauge | 当前可用解析许可数；持续为 0 表示解析器已被卡死的解析拖垮 |
| `resolver.timeout` | counter | 调用方等待解析超时的次数；此时许可仍被该解析持有，直到底层 lookup 返回 |
| `resolver.exhausted` | counter | 因无可用许可而被立即拒绝的解析次数 |

- 指标通过 `/actuator/metrics/{name}` 拉取，进程重启后归零。
- 进入许可耗尽状态时记录一条 `warn`，许可恢复可用时记录一条 `info`；单次解析超时记为 `debug`。日志中的目标主机名会剥离换行符，避免日志注入。
- 许可耗尽落库为 `DNS_RESOLVER_EXHAUSTED`，与目标侧故障区分；真实 DNS 失败与解析超时仍归类为 `CONNECTION_FAILED`。两种情况 Monitor 都置为 `DOWN`。

## 安全
必须遵守 `docs/architecture/security.md` 中的 SSRF 规则。不要在日志中记录敏感请求头或完整响应正文。

## MVP 非目标
不实现浏览器渲染、JavaScript 页面执行、复杂 API 契约检查或多地区探测。
