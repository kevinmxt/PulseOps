# 最小可用 UI 规范

## 目标

让个人开发者仅通过浏览器完成监控闭环：登录后查看监控项与当前状态、创建与编辑配置、启用/禁用与删除、查看历史结果与 Incident、配置心跳并获取上报命令，以及修改管理员密码。管理 UI 必须通过真实会话访问；生产静态托管与公网发布属于 Phase 5。

## 信息架构与路由

| 路径 | 用途 |
|---|---|
| `/login` | 公开登录页 |
| `/monitors` | 监控项列表（登录后默认入口） |
| `/monitors/new` | 创建监控项 |
| `/monitors/:id` | 监控详情：配置摘要、当前状态、历史结果、活动 Incident |
| `/monitors/:id/edit` | 编辑监控项 |
| `/incidents` | Incident 列表，支持状态过滤与按监控项过滤 |
| `/settings` | 修改管理员密码 |

- 导航栏包含「监控项」与「Incidents」，顶栏另显示用户名、「设置」入口与「登出」。
- 未认证访问管理路由时跳转 `/login?redirect=<站内路径>`；登录后回到原路径。
- 已认证访问 `/login` 时直接进入 `/monitors`。
- 浏览器前进/后退与直接访问深层链接必须可用。
- 未知路由显示明确的未找到页面。
- 界面文案使用中文；状态与失败类型可保留服务端枚举作为辅助信息。

## 认证与账号

- 认证状态只保存在内存，不写入 `localStorage`/`sessionStorage`；刷新页面通过 `GET /api/v1/auth/session` 恢复。
- 所有非 GET 请求携带 `X-XSRF-TOKEN`；收到 403 `CSRF_INVALID` 时重新调用会话引导并重试一次，再次失败直接提示错误。
- 任一管理请求返回 401 时清空认证状态并跳转 `/login?redirect=<当前站内路径>&expired=1`；登录与会话引导请求不触发全局跳转。
- 登录页对 401 显示通用「用户名或密码错误」；对 429 显示 `Retry-After` 对应的可重试秒数。
- 登录成功后只接受以单个 `/` 开头的站内回跳路径；其他情况进入 `/monitors`。
- 登出后清空本地状态并回到登录页；登出请求失败也必须回到登录页。
- `/settings` 表单校验当前密码、新密码长度（12–128）与两次输入一致；服务端返回当前密码错误时就地提示。
- 改密成功后提示「请重新登录」并跳转登录页；不得在 URL、存储或日志中保留密码。

## 监控项列表

- 每行展示：名称、类型、Monitor Status、最近检查时间、Probe Latency、操作。
- 类型标签区分 `HTTP` 与 `Heartbeat`。
- Monitor Status 显示为「正常 / 故障 / 未知」，对应 `UP` / `DOWN` / `UNKNOWN`；详情页保留原始枚举。
- 禁用的监控项优先显示「已禁用」，并以次要信息保留最后已知状态；不得把禁用等同于故障。
- Probe Latency 显示最近一次 Probe 的耗时，单位毫秒；无历史时为「—」；Heartbeat Monitor 恒为「—」。
- 最近检查时间使用相对时间（如「3 分钟前」），悬停显示绝对本地时间；历史表格使用绝对时间。
- 分页使用服务端统一信封；UI 页码从 1 开始显示，服务端 `page` 从 0 开始。
- 列表在标签页可见时每 30 秒自动刷新，并提供手动刷新按钮；所有变更操作完成后立即重新加载当前页。
- 删除当前页最后一项后，回到仍有数据的上一页。
- 列表为空、加载失败、请求进行中必须有明确状态提示。
- Phase 4A 不提供监控项搜索或状态过滤。

## 创建与编辑

- HTTP 监控项常用字段：名称、Target URL、方法、间隔、启用状态。
- HTTP 高级字段折叠展示但可编辑：连接超时、响应超时、期望状态码范围、失败阈值、恢复阈值。
- Heartbeat Monitor 只显示：名称、预期间隔、宽限时间、启用状态。
- `type` 创建后不可变；编辑请求保留原类型。
- 编辑时必须使用服务端返回的值回填表单；创建时的默认值必须与 API 文档一致，并由前端单一常量维护。
- 更新使用整体替换语义：提交全部可配置字段；列表行内启用/禁用同样提交完整配置。
- 名称必填；Target URL 必须是合法的 HTTP/HTTPS 地址；数值字段遵守服务端定义的范围。
- 客户端校验失败时就近提示；服务端错误统一显示在表单顶部，包含稳定错误代码、消息与 `traceId`。
- 删除监控项必须二次确认；禁用不需要确认。
- 创建 HTTP 监控项成功后进入详情页；创建心跳监控项成功后进入一次性令牌展示流程。

## 监控详情

- 展示完整配置摘要、启用状态与 Monitor Status（两者分开显示）。
- 展示最近检查时间、最近成功时间；心跳监控项额外展示最近心跳时间。
- 历史结果分页展示：开始时间、结果、失败类型、HTTP 状态码、耗时、错误摘要。
- 历史为空时显示空状态。
- 展示该监控项的 OPEN Incident；提供「查看全部」链接到按 `monitor_id` 过滤的 Incident 页。
- 心跳监控项展示预期间隔与宽限时间；令牌不会在详情页显示，提示需到编辑页轮换后重新获取。

## Incident 与通知状态

- Incident 列表支持在 OPEN 与 RESOLVED 之间切换，并接受 `monitor_id` 查询参数。
- 列表展示：监控项名称、状态、开始时间、恢复时间、失败类型、摘要，按开始时间倒序分页。
- 展开一条 Incident 显示最近 5 条 Notification Delivery：渠道、事件类型、状态、尝试次数、最后尝试时间、发送时间、错误摘要。
- 处于 `PENDING` 重试态的通知必须展示最近一次失败摘要；`SENT` 不显示错误摘要；终态 `FAILED` 保留摘要。
- 不提供单独的 Incident 详情路由；展开行为即可满足 Phase 4A。

## 心跳令牌与上报命令

- Heartbeat Token 只在创建成功或轮换成功后展示一次。
- 展示内容包括令牌本身与可复制的上报命令：`curl -fsS -X POST <origin>/api/v1/heartbeats/<token>`。
- 命令中的主机名使用当前页面 origin；同时提示生产环境必须替换为实际域名。
- 令牌只保存在组件内存：不得写入 `localStorage`/`sessionStorage`、不得放入 URL、不得输出到控制台；离开页面即清除。
- 提供复制按钮与「我已保存」确认；剪贴板不可用时允许手动选择文本。
- 之后再次进入编辑页不显示令牌，只提供轮换与撤销；令牌已不可找回，需要重新获取时必须轮换。
- 轮换后旧令牌立即失效；撤销幂等；禁用状态下仍允许轮换与撤销。

## 刷新与实时性

- 列表页在 `document.visibilityState === 'visible'` 时每 30 秒轮询；页面隐藏时暂停。
- 详情页与 Incident 页只在进入、手动刷新和变更后重新加载。
- 刷新失败保留上一次成功数据，并显示可重试的错误提示。

## 时间与时区

- 服务端时间按 UTC 存储；UI 按浏览器时区显示。
- 相对时间用于最近检查与最近心跳；绝对时间格式为 `YYYY-MM-DD HH:mm:ss`。
- 空时间显示「从未」或「—」，不得显示伪造时间。

## 错误处理与边界

- 统一解析服务端 `{code, message, traceId}` 错误结构，不展示堆栈或内部细节。
- 网络失败、超时与非 JSON 响应提供通用错误提示。
- 资源已被删除导致 404 时，提示并返回列表。
- 不扩展字段级错误契约；字段定位依赖客户端校验与服务端消息。
- Phase 4A UI 仅通过本地 Vite 代理访问回环地址上的管理 API；不得改变后端默认监听边界。

## 可访问性与可读性

- 状态不得只依赖颜色表达，必须有文字标签。
- 表格、表单控件与按钮具备可读标签与键盘焦点。
- 令牌、URL 等技术内容使用等宽字体。
- 基本窄屏适配；不实现专门的移动端布局。

## 非目标

- 监控项搜索、状态过滤与批量操作。
- 图表大屏、自定义仪表盘、主题切换与国际化。
- 生产静态托管、公网发布与多用户。
- 端到端浏览器自动化测试。
- 扩展服务端字段级错误结构。
