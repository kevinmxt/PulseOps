# Heartbeat 心跳监控规范

## 目标
让后台任务、脚本和定时作业主动报告执行成功，以发现任务停止、延迟或未执行的问题。

## 创建心跳监控项
每个 Heartbeat Monitor 至少配置：
- 名称
- 预期执行间隔
- 宽限时间
- 启用状态

创建后生成独立的高强度随机令牌。令牌只在创建或重新生成时显示一次；数据库保存安全摘要。

## 上报接口

路径：`POST /api/v1/heartbeats/{token}`

- 有效令牌返回 `204`，更新最后心跳、最后检查和最后成功时间，状态置 `UP`，顺延截止时间，并写入一条成功 CheckResult。
- 无效、已撤销、不存在或所属监控项已禁用的令牌统一返回 `404 HEARTBEAT_NOT_FOUND`，不区分原因。
- 不要求后台任务使用管理员登录凭证。
- 不得将完整令牌写入日志。
- 按令牌 SHA-256 摘要限流 120 次/分钟（无效令牌同样计数），超出返回 `429` 并带 `Retry-After`。
- 请求体上限 1KB，超出返回 `413`。
- `pulseops.heartbeat.require-https` 开启时，仅接受原生 TLS 或 `X-Forwarded-Proto: https`，否则返回 `400`。

## 令牌轮换与撤销

- `POST /api/v1/monitors/{id}/heartbeat-token`：在同一事务内撤销旧凭证并生成新凭证，返回仅此一次可见的新令牌；旧令牌立即失效。禁用状态的监控项仍允许轮换。
- `DELETE /api/v1/monitors/{id}/heartbeat-token`：撤销当前凭证，幂等返回 `204`；禁用状态的监控项仍允许撤销。
- 撤销或轮换不删除历史凭证记录，保留审计信息。

## 超时与恢复
- 若当前时间超过最后一次有效心跳时间加允许间隔和宽限时间，则判定超时。
- 未收到过任何心跳时，应按创建时间和明确的首次执行宽限规则处理。
- 超时扫描必须幂等。
- 同一持续故障只允许一个未解决的 Incident。
- 收到新的有效心跳后，按约定恢复规则关闭 Incident。
- 心跳规则独立于 HTTP 连续失败阈值。

## 验收
- 有效令牌可上报。
- 无效或撤销令牌被拒绝。
- 令牌不会明文持久化或进入日志。
- 按时心跳不产生超时告警。
- 超时会产生故障事件。
- 恢复心跳会正确关闭事件。
- 重复扫描不会创建重复事件。
