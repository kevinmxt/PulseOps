# Heartbeat 心跳监控规范

## 目标
让后台任务、脚本和定时作业主动报告执行成功，以发现任务停止、延迟或未执行的问题。

## 创建心跳监控项
每个 Heartbeat Monitor 至少配置：
- 名称
- 预期执行间隔
- 宽限时间
- 启用状态

创建后生成独立的高强度随机令牌。令牌只在创建或重新生成时显示一次；数据库保存安全摘要。

## 上报接口
建议路径：`POST /api/v1/heartbeats/{token}`

- 必须通过 HTTPS 访问。
- 仅接受有效且未撤销的令牌。
- 不要求后台任务使用管理员登录凭证。
- 不得将完整令牌写入日志。
- 响应应简短且不泄漏内部信息。
- 请求应具备合理的速率和大小限制。

## 超时与恢复
- 若当前时间超过最后一次有效心跳时间加允许间隔和宽限时间，则判定超时。
- 未收到过任何心跳时，应按创建时间和明确的首次执行宽限规则处理。
- 超时扫描必须幂等。
- 同一持续故障只允许一个未解决的 Incident。
- 收到新的有效心跳后，按约定恢复规则关闭 Incident。
- 心跳规则独立于 HTTP 连续失败阈值。

## 验收
- 有效令牌可上报。
- 无效或撤销令牌被拒绝。
- 令牌不会明文持久化或进入日志。
- 按时心跳不产生超时告警。
- 超时会产生故障事件。
- 恢复心跳会正确关闭事件。
- 重复扫描不会创建重复事件。
