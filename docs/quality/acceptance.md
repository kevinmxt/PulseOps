# 验收与测试规范

## Definition of Done
功能完成必须满足所有适用项：
- 需求与产品规范一致。
- 已实现并完成代码自查。
- 业务行为变更有对应测试。
- 已实际运行相关测试。
- 构建成功，或明确记录环境阻塞。
- 没有新增已知严重安全问题。
- 数据库变更包含 Flyway 迁移。
- 必要文档已更新。
- Git diff 不包含无关修改。
- 不包含真实凭证或敏感数据。
- 验收条件有证据。
- 未完成事项已明确列出。

不能把代码已写完等同于生产部署已完成。

## 测试层级

### 单元测试
覆盖：
- 输入和 URL 校验
- 失败/恢复阈值
- Heartbeat 超时判断
- Incident 状态转换
- 告警去重
- 数据保留时间计算
- 错误分类

### 集成测试
覆盖：
- Flyway 迁移
- Repository 查询
- 外键和唯一约束
- 事务边界
- 并发创建 Incident
- 通知任务持久化
- 历史数据清理

PostgreSQL 行为应使用真实 PostgreSQL 或 Testcontainers 验证，不可完全依赖 H2 替代。

### 端到端测试
至少覆盖：
1. 创建 HTTP Monitor。
2. 成功探测。
3. 连续失败并创建 Incident。
4. 触发通知。
5. 服务恢复并关闭 Incident。
6. 发送恢复通知。
7. 创建 Heartbeat Monitor。
8. 心跳超时和恢复。

优先使用本地模拟服务，不依赖不可控的公网目标。

### 安全测试
覆盖未授权访问、非法 URL、私有地址、禁止的重定向、无效心跳令牌、超长输入和敏感日志检查。

## 初期性能验证
基础场景：100 个启用的 HTTP 监控项，平均 60 秒检查间隔。

记录测试条件、持续时间、探测延迟、失败率、线程池情况、内存和数据库负载。未经实际测试，不得宣称性能目标已达成。

## 完成报告格式
- 完成内容
- 修改文件
- 实际执行的命令及结果
- 风险和遗留问题
- 下一步建议
