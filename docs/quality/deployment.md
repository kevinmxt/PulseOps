# 部署与运维规范

## 目标环境
- 单台 Linux VPS。
- 建议起步配置：2 vCPU、4 GB RAM、40 GB 以上 SSD。
- Docker Compose。
- Spring Boot + PostgreSQL + Caddy。
- 域名和 HTTPS 用于正式公网部署。

预算目标为全部基础设施尽量低于 S$50/月。采购前需核实机房、税费、续费、流量和备份价格。

## 网络边界
- 仅公开必要的 HTTP/HTTPS 入口和受控的 SSH 入口。
- PostgreSQL 不直接暴露到公网。
- 使用独立且权限受限的数据库账号。
- 生产环境启用 HTTPS。
- 心跳令牌不得通过不安全的公开 HTTP 传输。

## 公网发布硬性门槛

- 任何管理入口（管理 API 或管理 UI）公网可达前，必须完成 Phase 4B 的单用户认证与授权。
- 反向代理（如 Caddy）只负责 TLS 终止、入口暴露和必要的网络控制，不视为唯一授权层；应用必须自行拒绝未认证请求并返回 401/403。
- 认证未启用时，不得将后端或管理入口公开监听或暴露到公网。
- Phase 4B 的验收项与完成状态见 [`../product/roadmap.md`](../product/roadmap.md)。

## 配置管理
- 真实凭证通过环境变量或安全部署配置提供。
- `.env.example` 只能包含占位值。
- 生产环境配置不得提交到 Git。
- 容器尽量以非 root 用户运行。
- 配置合理的重启策略、资源限制和日志轮转。

## 备份与恢复
- 定期备份 PostgreSQL。
- 明确备份保留期限和存放位置。
- 保护备份文件中的敏感数据。
- 必须执行至少一次恢复演练。
- 仅确认备份文件存在，不代表恢复能力已验证。

## 发布与回滚
发布前：
1. 运行测试和构建。
2. 检查迁移脚本。
3. 备份关键数据。
4. 检查环境变量和密钥。
5. 准备回滚方案。

发布后：
1. 检查应用健康状态。
2. 检查数据库连接和迁移状态。
3. 执行关键功能冒烟测试。
4. 检查日志和资源占用。
5. 确认外部监控能够探测服务。

## 独立外部监控
PulseOps 不应只依靠自己监控自己。应使用独立的外部服务检查 PulseOps 的健康端点，避免 VPS 宕机后告警系统同时失效。
