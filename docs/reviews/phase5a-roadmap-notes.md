# Phase 5A 路线图衔接建议

## 阶段结论

Phase 5A 的本地 VM 部署闭环已有较完整验收证据，可以进入 Phase 5B。Phase 5B 不应只是把 `pulseops.test` 改成真实域名，而要验证真实公网环境下的证书、外部探测、灾备和用户操作链路。

## Phase 5B 建议顺序

1. **真实 VPS 基线：** 确认系统版本、资源、SSH 密钥登录、云防火墙与 UFW 规则；保留控制台救援路径。
2. **域名与 TLS：** 配置 DNS 与 ACME，验证外部证书链、续期路径及 80→443 跳转。
3. **真实灾备：** 接入独立对象存储；age 私钥离线保管；启用外部备份成功/失败监控；实际下载远端副本并恢复。
4. **外部可用性监控：** 从 PulseOps 之外探测 HTTPS 健康端点，配置通知并演练告警。
5. **浏览器端到端验收：** 登录、会话过期、改密、监控 CRUD、探测失败/恢复、心跳、Incident、通知投递及 CSRF 边界。
6. **发布与恢复：** 真实 VPS 执行部署、健康门禁、回滚；若 schema 已前进，验证脚本阻止不安全回退并演练备份恢复。
7. **稳定性观察：** 观察至少 7 天，记录资源、日志、证书、备份、外部探测和告警结果。

## 公网开放门槛

以下任一项未完成，都应明确标记为“尚未生产就绪”，不要以本地 VM 验收代替：

- 真实域名和受信任的 ACME 证书已从外部网络验证。
- 真实远端加密备份可下载、解密、恢复并启动应用。
- 备份失败和服务不可达都能触发外部告警。
- 管理 UI 关键用户流程已在真实 HTTPS 域名下完成浏览器验收。
- SSH 救援方式、部署回滚和数据库恢复步骤有可执行的操作手册。

## 可延后加固

- 将 `postgres:17-alpine` 与 `caddy:2-alpine` 固定到经验证的 patch 版本或 digest，并建立定期更新策略。
- 为 Caddy/应用建立适度的结构化访问日志和隐私过滤规则。
- 评估 SSH 限速对自动化运维的影响，优先采用 SSH 连接复用，而不是无条件放宽防护。
