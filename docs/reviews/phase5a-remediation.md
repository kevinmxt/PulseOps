# Phase 5A 后续修正与 Phase 5B 验收清单

本文将审阅建议拆成可执行任务。P1 项目是 Phase 5B 公网开放门槛；P2/P3 为加固建议。

## P1 — 真实异地备份和外部告警

- [ ] 将 `BACKUP_RCLONE_REMOTE` 配置为独立于 VPS 的真实对象存储，使用专用最小权限凭据。
- [ ] 验证远端 bucket/路径不与 VPS 共用故障域；配置对象存储访问控制与生命周期策略。
- [ ] 将 `HEALTHCHECKS_PING_URL` 配置为真实服务 URL，确认成功 ping 与 `/fail` 失败 ping 都能到达并触发预期状态/告警。
- [ ] 模拟备份失败，确认 systemd `OnFailure` 运行且通知在外部可见。
- [ ] 下载最新真实远端加密对象，校验大小/可解密性，恢复到独立数据库，并启动应用验证健康端点及核心管理 API。
- [ ] 将 age 私钥离线保存并演练在新主机上取回密钥的流程。

验收证据：时间戳、远端对象标识、告警截图/事件 ID、恢复库验证输出、RPO/RTO 记录；不将本地目录 remote 或本地接收器作为真实异地/告警证据。

## P1 — 真实域名与公网端到端

- [ ] 配置真实 DNS、云防火墙和主机 UFW，确认仅预期端口开放。
- [ ] 配置真实 `SITE_ADDRESS` 与 ACME 邮箱/issuer，验证证书链、SAN、有效期与自动续期。
- [ ] 从非 VPS 网络验证 HTTP→HTTPS、根页面、匿名管理 API 返回 401、健康端点返回 UP。
- [ ] 用真实浏览器完成登录、会话过期、改密、监控创建/编辑/删除、历史结果、Heartbeat、Incident 和通知流程。
- [ ] 验证 `/actuator/metrics` 不被静态站点 fallback 误认为已开放的管理端点；确认真实请求返回的内容符合预期且不泄露内部指标。
- [ ] 验证 TLS 与认证 Cookie 配置正确，测试中不依赖 `--insecure`。

## P2 — 可重复构建与基础镜像更新

- [ ] 评估固定 `postgres:17-alpine`、`caddy:2-alpine` 的 patch 版本或 digest。
- [ ] 在 CI 中构建并验证更新后的镜像；记录升级与回退方法。
- [ ] 建立定期依赖/镜像漏洞检查与更新节奏，避免 pinning 演变成长期不更新。

## P2 — SSH 运维可靠性

- [ ] 在运维手册记录 `ufw limit 22/tcp` 的限速行为与等待恢复方法。
- [ ] 自动化脚本使用 SSH multiplexing/连接复用，避免连续建立过多连接。
- [ ] 确认云控制台/救援入口可用，防火墙或 SSH 配置变更前保留现有会话。
- [ ] 若需调整限速，先通过威胁评估和测试决定，不直接移除防护。

## P3 — 日志与持续运行

- [ ] 评估启用 Caddy 访问日志的价值和磁盘成本；确保不记录 Cookie、密码、认证头、心跳令牌或其他秘密。
- [ ] 配置外部 uptime、TLS 到期、备份失败与磁盘空间告警。
- [ ] 连续运行至少 7 天，记录服务重启、内存/CPU、磁盘、备份、外部探测与告警结果。

## 完成判定

P1 项全部通过后，才建议将 PulseOps 标记为具备真实公网试运行条件。P2/P3 可按资源安排进入后续迭代，但需在发布记录中明确未完成项。
