# Phase 4B 完成后的路线建议

## 结论

Phase 4B 可按 `docs/quality/phase4b-acceptance.md` 中的 CI 与本机验收证据视为完成，下一阶段进入 **Phase 5：VPS 部署**。本阶段已补齐单用户管理认证、CSRF/会话、历史数据保留与清理、备份恢复演练，以及 Phase 4A 前端遗留项修正。

## Phase 5 建议顺序

1. **部署边界先做**
   - 生产 Compose 配置与非 root 运行。
   - Caddy 终止 TLS，应用继续只绑定回环地址；PostgreSQL 不暴露公网。
   - 配置防火墙、SSH 密钥登录、最小端口开放。
   - 明确反向代理可信来源与客户端 IP 传递策略；不要信任任意客户端提供的转发头。

2. **秘密与生产配置**
   - 通过部署环境注入数据库密码、管理员引导凭据、Telegram 凭证等。
   - 确认首次管理员创建后移除 bootstrap 变量。
   - 验证 Secure Cookie、HTTPS 与心跳上报 HTTPS 策略。
   - 确认日志不包含密码、Session ID、CSRF Token 或完整心跳令牌。

3. **备份与恢复**
   - 配置定时备份、保留数量、异地存储和可选加密。
   - 设置备份失败告警与磁盘空间监控。
   - 在 Linux VPS 上验证脚本执行位、目录/文件权限，并补做恢复中途失败的清理演练。
   - 定期恢复到独立数据库，不以“备份文件存在”代替可恢复性。

4. **运行观测与回滚**
   - 配置日志轮转、资源限制、健康检查和容器重启策略。
   - 准备升级、迁移、回滚步骤。
   - 配置独立于 PulseOps 的外部健康检查，避免被监控服务宕机后告警也失效。
   - 记录 CPU、内存、磁盘、数据库体积、探测延迟、通知延迟与失败率。

5. **安全加固小项**
   - 在公开公网入口前，建议加固登录限流的并发配额与容量上限驱逐行为（详见 `phase4b-review.md`）。
   - 只有在真实需求出现后再考虑持久会话、多实例调度或 Redis；当前继续保持单实例约束。

## 公网发布门槛

Phase 4B 完成并不代表可以直接公开。必须先完成 TLS/反向代理、防火墙、可信代理头配置、秘密管理、备份恢复验证、日志轮转和回滚准备。公网开放后应先进行小范围冒烟测试，再开始至少 7 天的连续运行观察。
