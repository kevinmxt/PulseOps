# 安全规范

安全要求是 MVP 的必需条件。

## SSRF 与目标 URL
用户可配置目标 URL，因此所有探测目标均视为不可信输入。

必须：
- 只允许 HTTP/HTTPS。
- 拒绝 localhost、私有地址、链路本地地址和云元数据地址。
- 对解析后的 IP 执行校验。
- 考虑 DNS 重绑定风险。
- 对重定向执行严格限制；禁止未经校验跳转到受限地址。
- 设置连接、响应和响应体大小限制。
- 创建时和每次执行时都进行必要校验。

不能可靠防护时，缩小允许访问范围；不能只在创建时检查 URL 一次。

## 认证与授权
- 公网管理界面必须启用认证。
- 密码使用成熟的安全哈希算法。
- 正确配置 Cookie / Session 安全属性。
- 根据认证方式实施 CSRF 防护。
- 对登录失败进行限制。
- 对受保护接口进行未授权访问测试。
- 所有管理操作都要检查权限。

## 密钥与敏感信息
- 不将真实密钥、密码、Bot Token 或私钥提交到 Git。
- 使用环境变量或安全部署配置注入密钥。
- `.env.example` 只允许占位值。
- 不记录完整心跳令牌、密码和敏感请求头。
- 默认不记录被监控 API 的完整响应正文。
- 错误摘要必须截断并避免敏感信息。
- 不向用户返回内部堆栈、连接串或环境变量。

## 网络和部署
- PostgreSQL 不直接暴露到公网。
- 生产环境使用 HTTPS。
- 关闭无必要的公网端口。
- SSH 优先使用密钥认证。
- 使用权限受限的数据库账号。
- 保护备份文件和日志。
- 管理 API、心跳凭证和公开状态页必须具有清晰的权限边界。

## 安全测试最低范围
- 非法 URL 和协议
- localhost / 私有 IP / 链路本地地址
- 重定向到禁止地址
- 无效或撤销的心跳令牌
- 未认证访问管理接口
- 敏感信息日志检查
- 超长输入和非法配置
